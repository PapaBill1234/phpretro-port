# Direct DeepSeek and subscription Codex

The active provider registry no longer routes through A6API. Native Claude workers use DeepSeek V4.1 Flash directly at https://api.deepseek.com/anthropic, with main model `deepseek-flash[1m]` and discovery/research agents `deepseek-flash`. Sol IDs never go to that endpoint; DeepSeek can silently map unsupported names.

Run offline setup checks with `python3 scripts/claude-builder.py --role worker --check` (or `--status`). Credential precedence is DEEPSEEK_API_KEY, PHPRETRO_DEEPSEEK_ENV, secrets/deepseek.env, then ~/.hermes/.env; private dotenv is parsed as data, never sourced. Actual worker launch first reads official provider balance and pauses for unavailable or nonpositive funding. No DeepSeek inference is needed to prepare this implementation. This preflight is not a monetary budget or concurrency supervisor; Eliza must enforce at most four claimed workers.

`--role worker --prepare` writes owned private0700/0600 .builder/provider-settings/settings.json with no key and performs no requests. Metadata includes settings_path, config_home, main_model, subagent_model, credential_source and worker_slots_directory. Managed ACP loads the key privately and consumes these reviewed settings; preparation itself does not authorize launch. The integration-owned scripts/deepseek-slots.py wrapper is required for real launch, and shared by ACP. The integration-owned helper derives its four locks from the actual git-common-dir/phpretro-builder/deepseek-slots, identical across linked worktrees; there is no registry override. It enforces the four-worker cap separately from funding; absent wrapper blocks dispatch.

Worker launch preserves native Claude Doctor, authorized bypassPermissions, worktree isolation, judge-only MCP and existing .builder/claude history. Role lead/backup/reviewer opens native Codex with the selected existing ChatGPT login and exact gpt-6.1-sol; reviewer uses read-only, others workspace-write/on-request. These roles perform subscription/quota readiness before opening. No API credentials are forwarded and no login/logout/reset-credit/account-switch operation is performed. Interactive subsequent turns rely on Codex and the operator; this launcher does not continuously monitor an interactive session. Codex history stays in its selected CODEX_HOME, separately from Claude. Existing wrappers and tmux names must be updated by integration; old already-open processes retain old routing until safely replaced.

## Bounded Eliza bridge contract

`python3 scripts/codex-bridge.py status` and `limits` perform installed RPC readiness without a model turn. `report` returns cached metadata explicitly unsuitable for dispatch. JSON stdout uses schema `phpretro.codex.bridge.v1`, ok, command, provider, model, status, limits and model_available. Errors use sanitized error.code/message and exit2. A model catalog entry is not proof of entitlement; model_access_verified stays false until a matching completed help turn.

`help --task-id G06 --reason final-review --prompt-file /private/review.md --timeout 180` requests bounded read-only Sol help. Reasons architecture/final-review are authorized checkpoints. Retry requires --reason retry and --failures-file /private/failures.json with tasks.G06.failures at least3; file must be owned regular0600. Only the trusted local coordinator supplies these paths; this CLI is not a public authorization API. Funding failures do not count. Default help timeout180s, maximum300s; other calls default30s. --state-dir defaults .builder/codex-bridge and is private0700. Requests serialize with an exclusive lock; account fingerprint, repository, task and reason bind durable thread IDs. No raw account identity, auth tokens, RPC errors or provider logs enter stdout. Native private history persists.

Quota comes from all reported windows, preferring rateLimitsByLimitId. At10%remaining or unknown/stale/malformed metadata, new help pauses. Durations300/10080 are five hours/seven days; daily_available requires an actual1440-minute window. Owner account switching is manual followed by fresh readiness. Successful help requires the exact thread/turn completed status and final assistant message. Failed/interrupted/EOF/invalid/oversized/timeout results fail; timeout sends interrupt and terminates the process group, including descendants. Approval/dynamic-tool requests are denied; source review uses the installed read-only policy with networkAccess=false. Installed0.162.0 cannot restrict readable roots; scoped read instructions are not filesystem credential isolation.
